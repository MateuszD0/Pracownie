# Ocena alertów

Priorytet i pewność są osobne. **Wysoki priorytet** oznacza komunikat o promocji, dodatku lub warunkach, albo zmianę nagłówka, baneru czy wezwania do działania. **Standardowy** oznacza pozostałe obserwacje. To reguła porządkująca, nie dowód wpływu na sprzedaż. Oznaczenie „Do sprawdzenia”, „Zaobserwowana zmiana” albo „Sprawdzono w serwisie” opisuje podstawę odczytu; nawet sprawdzenie serwisu nie jest testem zakupu.

## Jak ocenić alert

1. W dashboardzie kliknij „Przed / po” przy alercie i sprawdź zapis oraz źródło.
2. Wybierz „Trafny”, „Nietrafny” albo „Nie wiem”. Otworzy się wstępnie wypełnione zgłoszenie GitHub. Zapisz je przyciskiem **Submit new issue**; samo otwarcie formularza nie zapisuje oceny. Możesz dopisać komentarz.
3. Repozytorium jest publiczne: zgłoszenie i komentarz też będą publiczne. Potrzebne jest zalogowanie na GitHubie.
4. Zgłoszenie jest trwałe. Podsumowanie i ewentualne oznaczenie przy alercie odświeżą się przy następnej publikacji raportu. Jeśli ocenisz ten sam alert ponownie, liczy się najpóźniej zaktualizowana ocena. Wcześniejsze wydania HTML pozostają dostępne w historii dni.

Przy porównanej stronie pracowni znajduje się także „Zgłoś pominiętą zmianę”. Po opisaniu i zapisaniu zgłoszenia będzie widoczne w liczbie zgłoszeń. To zgłoszenia od użytkownika, nie automatycznie potwierdzone przeoczenia.

## Co oznacza liczba trafnych

Wskaźnik to **liczba alertów ocenionych jako trafne / liczba alertów ocenionych jako trafne lub nietrafne** z ostatnich 180 dni. „Nie wiem” jest liczone osobno. Dashboard pokazuje liczbę ocenionych i zapisanych alertów; brak ocen nie jest wynikiem 0%. Oceniona próba może nie być reprezentatywna dla wszystkich alertów. Liczba pominiętych zmian nie wyznacza skuteczności wykrywania: do tego trzeba ocenić również reprezentatywną próbkę stron bez alertów.

Monitor uwzględnia tylko zgłoszenia od właściciela, członków organizacji lub współpracowników repozytorium, dotyczące rzeczywistych zdarzeń w rejestrze. Zmiana treści tytułu lub identyfikatora może uniemożliwić rozpoznanie oceny. Gdy odczyt GitHub Issues jest niedostępny, dashboard informuje o braku możliwości odczytu, a nie pokazuje zerowej trafności. Żadna ocena nie zmienia zapisanego materiału ani nie usuwa dowodów.
